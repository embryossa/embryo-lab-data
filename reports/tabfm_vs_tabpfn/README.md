# TabFM 1.0.0 против TabPFN-3 на данных эмбриологической лаборатории

Независимое сравнение двух табличных foundation-моделей на задаче прогноза наступления беременности после переноса. Прогон выполнен отдельно от аналитического пайплайна: ни один файл пайплайна не изменялся, результаты получены на заново собранных матрицах признаков.

Дата прогона: 2026-09-18. Источник предсказаний: `clinics_ctx2000.parquet`.

---

## Краткий итог

1. **Различающая способность обеих моделей на этих данных слабая и между собой неотличима.** На основной панели (Fertimed, n = 250) ROC-AUC составил 0.587 у TabFM против 0.596 у TabPFN-3 при продакшн-входе; разность -0.0087 (95% ДИ -0.0526…+0.0362, p = 0.709) статистически незначима. Ни одна из моделей не поднялась выше AUC 0.60.

2. **Устойчивое и воспроизводимое преимущество TabFM — в калибровке, не в ранжировании.** На обоих вариантах входа Fertimed TabFM даёт значимо меньшие Brier, log-loss и ECE: при продакшн-входе Brier 0.246 против 0.266 (Δ = -0.0195, p = 0.001), ECE 0.075 против 0.156. Наклон калибровки у TabFM (0.529) ближе к единице, чем у TabPFN-3 (0.383). Практически это значит, что числу, которое выдаёт TabFM, можно доверять как вероятности заметно больше, хотя порядок пациентов по риску он расставляет не лучше.

3. **Оба варианта входа систематически занижают прогноз.** Средний прогноз 0.416 (TabFM) и 0.307 (TabPFN-3) против фактической доли беременностей 0.452. Причина общая для обеих моделей — базовая частота в обучающем контексте (0.320) ниже, чем в когорте Fertimed, и in-context-модель наследует приор контекста. TabPFN-3 занижает сильнее.

4. **TabFM заметно чувствительнее к качеству входа.** При переходе от продакшн-подстановок к нативным колонкам TabPFN-3 деградирует (AUC 0.596 → 0.522, Brier 0.266 → 0.302), тогда как TabFM держится (AUC 0.576, Brier 0.256), и именно на этом варианте его превосходство становится значимым уже и по ранжированию: Δ ROC-AUC = +0.0545 (+0.0045…+0.1105, p = 0.034). Это наблюдение на одной панели и требует подтверждения.

5. **На Two-Line (n = 36) различить модели невозможно.** Ширина 95% ДИ для ROC-AUC — около 0.4, все парные разности незначимы (p от 0.14 до 0.99), а формально лучший результат показывает логистическая регрессия (AUC 0.629). Панель приводится для полноты, выводов из неё делать нельзя.

6. **Цена вопроса несопоставима.** Фит TabFM на контексте 2000 строк — 2553 с против 45 с у TabPFN-3 при чекпоинте 6.2 ГБ против 203 МБ, и это при урезанном ансамбле (4 члена вместо 32). Веса TabFM лицензированы только для некоммерческого и непродакшн-использования.

**Проверка на утечку.** Точных совпадений 18-мерных векторов признаков между клиническими панелями и обучающим контекстом нет: 0 из 250 для Fertimed и 0 из 36 для Two-Line.

**Проверка корректности сборки признаков.** Чтобы убедиться, что заново собранная матрица признаков идентична той, что строит продакшн-путь, TabPFN-3 был прогнан на панели Two-Line в точной штатной конфигурации пайплайна (контекст 5000 строк, стратифицированная выборка, seed 42) и результат сопоставлен с `data/processed/tabpfn_predictions.csv` текущего прогона. Совпали все 36 строк: средний модуль расхождения 0.0000, максимальный 0.0001, корреляция 1.0000. Матрица признаков воспроизведена верно, и различия между моделями ниже не объясняются ошибкой подготовки данных.

**Два варианта входа.** Продакшн-путь пайплайна подставляет в четыре колонки суррогаты: «дробящихся на 3-й день» и «эмбрионов 5-го дня» ← 2PN, «заморожено» ← бластоцисты хорошего качества, «перенесено» ← 1. В обучающем контексте в этих колонках стоят реальные значения. Поэтому каждая клиника прогонялась дважды: в продакшн-варианте (как пайплайн кормит TabPFN сегодня) и в нативном (реальные колонки выгрузки). Рассогласование обучения и инференса бьёт по обеим моделям одинаково, но его величина сама по себе информативна.

## 4. Протокол сравнения

Контекст: стратифицированная подвыборка **2000 строк** из обучающего датасета (16 056 циклов). Взято **2** независимых подвыборки (сиды 7, 42); предсказания усреднены по подвыборкам, разброс по отдельным сидам приведён в CSV.

Размер контекста выбран из вычислительного бюджета: продакшн-путь TabPFN использует 5000 строк, но фит TabFM на 5000 строк на этой машине — порядка часа на каждый ансамблевый член. Обе модели получают **байт в байт одинаковый контекст и одинаковые запросы**, поэтому сравнение между ними корректно; абсолютные значения метрик TabPFN-3 при этом чуть ниже, чем в штатной конфигурации пайплайна.

Модели сравнения: логистическая регрессия со стандартизацией, HistGradientBoosting, и базовая ставка (константа, равная доле беременностей в контексте) — последняя задаёт уровень, ниже которого модель бесполезна.

Метрики. **ROC-AUC** и **PR-AUC** — различающая способность, не зависят от калибровки. **Brier** и **log-loss** — общее качество вероятностного прогноза. **ECE** — средняя по децилям абсолютная разница между предсказанной и фактической частотой. **Наклон и сдвиг калибровки** — коэффициенты регрессии `logit(y) ~ a + b·logit(p)`; идеал b = 1, a = 0, значение b < 1 означает, что прогнозы слишком разбросаны относительно реальности. Доверительные интервалы и разности — стратифицированный бутстрэп, 3000 повторов; разности считаются **парно**, на одних и тех же перевыборках строк.

## 6. Ограничения

1. **Мощность.** При n = 36 (Two-Line) 95% ДИ для ROC-AUC имеет ширину около 0.4 — на этой панели никакое различие между моделями обнаружить нельзя, и приведённые числа следует читать как описание, а не как результат сравнения. Содержательные выводы опираются на панель Fertimed (n = 250).
2. **TabFM работал не в полной конфигурации.** `n_estimators=4` вместо 32, без SVD-признаков, без перекрёстных признаков и без Platt-калибровки, которые образуют заявленный Google вариант TabFM-Ensemble. Это смещает сравнение **против** TabFM: его реальный потолок выше измеренного здесь.
3. **Контекст 2000 строк вместо 16 056.** Обе модели ограничены одинаково, но ни одна не показана на полном объёме доступных данных.
4. **Размер выборок вне заявленного диапазона TabFM.** TabArena, на котором мерили TabFM, содержит наборы от 700 наблюдений; клинические панели здесь меньше.
5. **Лицензия.** Веса TabFM запрещены к коммерческому и продакшн-использованию. Для исследовательской публикации это допустимо, для встраивания в клинический пайплайн — нет.
6. Прогон на одной машине без GPU; относительные времена не переносятся на GPU/TPU-сценарий напрямую.

## 7. Воспроизведение

```
prep.py           # сборка трёх панелей из исходных выгрузок
run_clinics.py --ctx 2000 --seeds 42,7 --tabfm-n-est 4
make_report.py preds/clinics_ctx2000.parquet
```

Скрипты прогона лежат в `scripts/` рядом с этим файлом: `prep.py` (сборка панелей), `evalkit.py` (метрики и бутстрэп), `run_clinics.py` (прогон моделей), `make_report.py` (сборка этого отчёта), `verify_features.py` с выводом в `verify_features_output.txt` (сверка с пайплайном).

Рабочая папка прогона: `tabfm_workdir` из `config/research_paths.local.json` (изолированное окружение `.venv`, клон `google-research/tabfm`, сырые предсказания в `preds/`). Машинно-читаемые таблицы лежат рядом с этим файлом: `metrics_*.csv`, `delta_tabfm_minus_tabpfn_*.csv`, `covariate_shift.csv`.
