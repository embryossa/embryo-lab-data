---
description: Поднять self-hosted Teable + вьюер карточек (Docker) и синхронизировать processed-файлы всех клиник одной командой
---
Отдельная от `/run-analysis` задача — только подъём self-hosted Teable, заливка уже
готовых `data/processed` файлов всех клиник и пересборка локального вьюера карточек
пациенток. Ничего не пересчитывает и не запускает анализ.

Клиники, их `base_id` и папки `processed` живут ТОЛЬКО в
`teable/teable_config.local.json` (секция `clinics`). Ни в этом файле, ни в bat-файлах
id баз не зашиты — новая клиника добавляется одной записью в конфиг.

1. Проверь контейнеры: `docker ps --format "{{.Names}}"` в
   `teable/self-hosted` (от корня репозитория). Если
   `self-hosted-teable-1` / `-db-1` / `-cache-1` / `-cards-1` не в списке или не `Up` —
   подними: `cd teable/self-hosted && docker compose up -d`. Если у самого Docker
   Desktop ещё не поднят движок (`docker ps` падает с ошибкой pipe/daemon), сначала
   запусти `Docker Desktop.exe` и подожди, пока `docker ps` не перестанет падать
   (проверяй раз в 5-10 сек, не дольше ~2 минут).
2. Дождись готовности API: опроси `curl -s http://127.0.0.1:3000/health` пока не
   вернётся `{"status":"ok",...}` (обычно 5-15 сек после `docker compose up -d`,
   дольше — если образы ещё не скачаны).
3. Схема (идемпотентно, ничего не удаляет): рабочая директория `teable/`,
   `python teable_bootstrap.py --all`. Клиника без `base_id` получит новую базу,
   и id будет вписан в конфиг автоматически; у существующих баз досоздаются недостающие
   таблицы, поля и вкладки, а затем интерфейс выравнивается по эталону схемы (названия и
   порядок таблиц, порядок вкладок, порядок и видимость колонок), чтобы все клиники
   выглядели одинаково. Фильтры, сортировки и данные при этом не трогаются.
4. Синхронизируй все клиники разом, пробрасывая `$ARGUMENTS` как есть (например
   `--force`, `--dry-run`, `--no-files`, `--clinic ggrc`):
   `python teable_sync.py --all $ARGUMENTS`
   Эта же команда в конце пересобирает карточки пациенток (`cards_build.py`);
   отключается флагом `--no-cards`.
5. Ретранслируй пользователю ровно то, что напечатала команда (строки
   `Parsed: N patients, M with outcome (+K)`, счётчики по таблицам, `Done.`/`[skip]`/
   ошибку) — не переформулируй и не досчитывай числа сам. В конце дай две ссылки:
   базы `http://127.0.0.1:3000`, карточки `http://127.0.0.1:8788`.

Если в `Cycles` добавились новые поля, а прогон при этом не менялся, дозаполнить их
можно без создания лишней записи в `Runs`: `python teable_sync.py --all --cycles-only`.

Рабочая вкладка владельца — **🔎 Поиск пациенток** на таблице `Cycles`: поиск по ФИО /
ID / `cycle_uid` по всей базе клиники, снимок последнего прогона прямо в строке и ссылка
«Карточка» на полную карточку цикла. Не отправляй его в ревью-лист за поиском пациентки.

Повторный запуск на тех же файлах безопасен: прогон помечен хешем содержимого
`dt_predictions.csv` и будет пропущен с `[skip]`, пока не передан `--force`.
