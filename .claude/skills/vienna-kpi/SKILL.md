# Vienna Consensus KPI (PMID 28784335)

Формулы (реализованы в src/embryo/kpi.py):
- FR    = 2pN / MII при известном MII, иначе 2pN / Inseminated (в лаборатории все циклы ICSI)
- ClR   = дробящиеся / 2pN       — частота дробления
- BlR   = Bl / 2pN               — частота формирования бластоцист
- TGBDR = Good Bl / 2pN          — частота хороших бластоцист
- OCCR  = OCC / follicles        — частота получения ОКК
- MIIR  = MII / OCC              — maturity rate; только при фактически известном MII
- 3pNR  = 3pN / OCC ;  DegR = Degrade / MII

**Знаменатель TGBDR — 2pN, а НЕ число бластоцист.** Это единственная метрика, у которой
знаменатель расходится с одноимённым показателем модельного слоя: CSDI (и наша воронка,
строка `Bl→Good`) считают долю хороших от ВСЕХ бластоцист (`good/Bl`), а TGBDR — от 2pN.
Одна и та же лаборатория даёт `Bl→Good` ≈ 70% и TGBDR ≈ 43% одновременно; это не
противоречие. Мост: `TGBDR = (Bl→Good) × BlR`. Никогда не сравнивать `Bl→Good` или
модельную good-rate с порогами TGBDR (30%/40%) — сравнение с ними допустимо только для
величины с знаменателем 2pN. Подробнее — skill `dt-ensemble`.

## Показатель выше 100% — не «испорченные данные» (решение владельца)

`ClR > 100%` (дробящихся больше, чем 2pN) и `MII > OCC` (то есть `MIIR > 100%`, и
следом прогноз воронки `OCC→MII` больше 1) — НЕ нарушение целостности данных и НЕ
повод объявить строку негодной. У обоих есть штатное эмбриологическое объяснение,
и называть их «data integrity / counting mismatch» запрещено:

- **ClR > 100% — неоптимальный тайминг оценки оплодотворения.** Часть зигот не попала
  в окно визуализации пронуклеусов и не была учтена как 2pN, но продробилась. Это
  наблюдение о ТАЙМИНГЕ проверки оплодотворения, а не о качестве учёта. Содержательный
  вывод: проверку стоит сдвигать, а не «уточнять правила подсчёта».
- **MII > OCC — в программу добавлены размороженные ооциты.** Витрифицированные
  ооциты (собственные или донорские) не входят в OCC свежей пункции, но попадают в
  число MII. Знаменатель относится к пункции, числитель — к программе.

Биномиальный 95% CI в таких строках не считается (`kpi.wilson_interval` возвращает
NaN): при numerator > denominator интервал математически не определён. Это ограничение
метода, а не приговор данным — сама доля остаётся в таблице и подлежит интерпретации
по причинам выше.

Для FR/ClR/BlR/TGBDR/OCCR/MIIR контроль нижний: значение ниже порога = сигнал.
Для DegR и 3pNR контроль верхний: значение выше порога = сигнал. В отчёте всегда
показываются direction, competency, benchmark и 95% CI. FR benchmark фиксирован 75%.

Пороги: OCCR 70%/85% (нижние границы диапазонов опроса Vienna), MIIR 75%/90%,
FR 65%/75% (competency Vienna ICSI + принятый владельцем локальный benchmark),
ClR 95%/99%, BlR D5 40%/60%, TGBDR D5 30%/40%, DegR ≤10%/≤5%,
3pNR <9%/<4.5% как верхний reference indicator. Не называть OCCR/MIIR/3pNR
формальными Vienna KPI: их класс явно хранится в `indicator_class`.

`Model_KPIScore` — композитный признак модели (возраст, фолликулы,
инсеминированные, FR, хорошие Bl); он точно повторяет формулу обучения и НЕ является
лабораторным KPI Vienna. На границе старой модели допустим алиас `KPIScore`.
KPI_ADJUSTMENTS: KPIScore -> (prob, CI) как быстрая KPI-оценка, независимая от DT/TabPFN.

Когортный показатель — только Σ numerator / Σ denominator, не среднее процентов строк.
Ноль — наблюдение; отсутствие — NaN. Не назначать протоколы — только интерпретация.

## Раздельные таблицы эмбриолог/врач

`kpi.EMBRYOLOGIST_METRICS = (FR, ClR, BlR, TGBDR, DegR, 3pNR)`,
`kpi.DOCTOR_METRICS = (OCCR, MIIR)`. Это ДВЕ отдельные таблицы — эмбриолог отвечает за
всё после получения ОКК, врач только за получение ОКК и зрелость. Никогда не сравнивать
доктора с эмбриологом по разным метрикам в одном выводе и не строить общую
таблицу/рейтинг, где оба типа персонала стоят рядом по разным KPI.

## Популяция лабораторных KPI

ВСЕ таблицы Vienna KPI — и Overall/Time/Method, и обе таблицы компетентности —
считаются на расширенной lab-популяции: по всем циклам выгрузки, без гейта
`transferred>0`/известный исход. Лабораторные KPI описывают, что лаборатория сделала с
полученными ооцитами, а не чем кончился перенос (владелец, 2026-07-31). Когорта отчёта
(с гейтом) остаётся источником только `KPI Cycle`, review-list и воронки.

Три ВЛОЖЕННЫХ набора исключений, каждый уже предыдущего:

1. `kpi.competency_exclusion_mask` — обе таблицы: цикл, ещё идущий на момент выгрузки,
   NO-retrieval, freeze-all (Cryo).
2. `kpi.funnel_exclusion_mask` — только эмбриолог: счётчики воронки этой строки
   перенесены МИС из другой пункции.
3. `kpi.embryologist_only_exclusion_mask` — только эмбриолог: цикл, не дошедший до
   инсеминации («Только пункция»), чьи фолликулы/ОКК/MII остаются полноценным
   наблюдением OCCR/MIIR реального врача.

Токены — в `columns.yaml` соответствующей клиники. Ни один из трёх не применяется в
review-list и OZEMA.

Цикл считается ещё идущим по ПУСТОЙ «Причине завершения программы ВРТ», если такая
колонка есть в выгрузке; отсутствие значения `Число Bl` — только запасной прокси для
клиник без неё. У ЗАКРЫТОГО цикла пустой счётчик ниже известной стадии — наблюдённый
0: иначе из знаменателя BlR/TGBDR уходят ровно те циклы, где бластоцист не получилось,
и показатель систематически завышается.

Фильтр `2PN != 0` действует везде, кроме врачебной таблицы: там сохраняются строки с
ПУСТЫМ 2PN, потому что OCCR/MIIR вычисляются выше стадии оплодотворения. Записанный
`2PN = 0` исключается всегда.

Ниже уровня компетентности (`competency_met == False`) — отдельный абзац «Поводы
задуматься» под таблицей, а не встроенная в таблицу оценка; формулировка — наблюдение
("повод для дополнительного разбора"), не вывод о конкретном специалисте.
