# Первичная подготовка данных 1С Fertimed (отдельно от основного пайплайна)

Это НЕ часть `scripts/run_analysis.py` / `src/embryo/clinics/fertimed.py`. Тот пайплайн
их не импортирует и не читает результат этого skill — независимые процессы. Этот
skill существует для случаев, когда нужна ТОЛЬКО очищенная таблица (для других
проектов по этой же клинике), без построения `cycle_uid`, без KPI/DT/TabPFN и без
канонических переименований колонок.

Правила ниже — owner-approved техзадание от 2026-07-19, применяются **на месте**, к
оригинальным заголовкам колонок исходного Excel — колонки не переименовываются, не
добавляются, не удаляются. Меняются только строки (фильтр когорты) и значения внутри
уже существующих колонок (заполнение пропусков либо полный пересчёт значения).

## Что делает `clean_fertimed_1c.py`

Единственный файл, полностью самодостаточный (только `pandas`/`openpyxl`/`numpy`,
никаких импортов из `src/embryo`) — специально, чтобы этот skill можно было целиком
скопировать в другой проект и запускать там без изменений.

```
python clean_fertimed_1c.py <входной .xlsx> [--output <путь>] [--sheet <имя_или_индекс>]
```

Без `--output` результат кладётся рядом со входом как `<имя>_cleaned.xlsx`.
Последняя строка stdout — **ровно** абсолютный путь к результату, ничего больше
(так вызывающий агент сможет надёжно взять его для ответа пользователю). Диагностика
(сколько строк отфильтровано, сколько пропусков заполнено) идёт в stderr.

**Фильтр строк** — применяется в этом порядке (итоговая маска — AND всех трёх, но
диагностика в stderr считает отсев пошагово, как в техзадании):
1. `Исход переноса` не пусто.
2. `Число инсеминированных` присутствует и численно — иначе строка удаляется сразу
   (только циклы, где реально проводили оплодотворение).
3. `Лечение` (без учёта регистра/пробелов) — одно из: криоперенос, икси, эко,
   эко + икси, получение як (реципиент). Пустые, «Только пункция», «Инсеминация»,
   «ПГТ на размороженных эмбрионах» отбрасываются. `Лечение` больше нигде не
   используется — это ненадёжный маркер реального метода оплодотворения (см. ниже
   про `IVF`/`ICSI`).

**Заполнение пропусков** (только реально пустые ячейки, если не указано иное).
Порядок важен: `Число MII` заполняется первым, затем `Число ОКК` подтягивается из
уже заполненного `Число MII`, затем `Количество фолликулов` — из уже заполненного
`Число ОКК`. Так как фильтр когорты гарантирует, что `Число инсеминированных`
известно у каждой оставшейся строки, у цепочки всегда есть с чего начать — пропусков
в этих трёх колонках после очистки не остаётся вообще:
- `Число MII` пусто → значение `Число инсеминированных` (то же правило, что в
  основном пайплайне: используем MII, если он реально известен, иначе Inseminated —
  см. CLAUDE.md). Применяется теперь ко всем строкам, а не только к чистому ЭКО.
- `Число ОКК` пусто → значение (уже заполненного) `Число MII`.
- `Количество фолликулов` пусто → значение (уже заполненного) `Число ОКК`. `КАФ`
  не используется вообще (известно, что вносится ненадёжно).
- `№ попытки` пусто → 1
- `День переноса` пусто → 5
- `АМГ` пусто → та же формула, что `normalize.impute_amh` (age/AFC/OCC,
  клип в [0.1, 12.0]); возраст парсится из текста ("34 года") только во
  временной переменной для формулы.
- `ИМТ`/`BMI` пусто → константа 24.0 (если такая колонка вообще есть в выгрузке
  — в текущем формате Fertimed её нет, шаг тогда просто no-op).
- `Эмбриолог, проводивший оплодотворение` пусто → `Эмбриолог на пункции`, если и там
  пусто → `Эмбриолог на переносе`. Именно эта колонка (после заполнения по
  приоритету) — KPI-релевантный эмбриолог; напрямую она часто теряется при выгрузке.
- `Врач на пункции` пусто → `Врач на переносе`. Это основной/KPI-релевантный врач.

**Полный пересчёт** (перезаписывает существующее значение для всех строк когорты,
не только пропуски):
- `Заморожено эмбрионов` = `Заморожено эмбрионов` + `Заморожено бластоцист`
  (`Заморожено бластоцист` при этом не трогается).
- `Возраст` — парсится из текста в число ("34 года"/"26 лет"/"31 год" → 34/26/31).
  Если распарсить не удалось — ячейка остаётся пустой (не подставляется никакой
  дефолт; дефолт 35 используется только внутри формулы АМГ, в выходную таблицу не
  попадает).
- `Исход переноса` — кодируется в 0/1: **1**, если в тексте ячейки встречается
  подстрока `+28` (то есть «+28 дней» — подтверждённая клиническая беременность,
  неважно одно- или многоплодная), иначе **0** (биохимическая беременность либо
  беременность не наступила). Фильтр когорты уже гарантирует, что эта ячейка
  непустая у всех оставшихся строк.

**Намеренно НЕ трогается** — эти колонки owner пометил как не используемые для
отчёта (донорские коды, ФИО суррогатной матери, исходы родов/осложнений, SMF, FET,
PGT-TVP/PGT-ET, КАФ и т.п.): они остаются в файле как есть, на своём месте, просто
ни в одном правиле выше не участвуют. Явно решено (2026-07-19) их не вырезать из
выходной таблицы.

## Как это используется

Команда `/reformat-1C-report <путь к .xlsx>` запускает выделенного субагента
`fertimed-1c-reformatter`, который загружает этот skill и выполняет
`clean_fertimed_1c.py` из этой же папки. Агент отчитывается только полным путём к
результату — сам файл в контекст агента не грузится (не нужно передавать целиком
персональные данные пациентов модели без необходимости).

Перенос в другой проект: скопировать всю папку `.claude/skills/reformat-1c-report/`
(plus `.claude/agents/fertimed-1c-reformatter.md` и
`.claude/commands/reformat-1C-report.md`, если нужен и сам вызов командой) — скрипт
не ссылается ни на что за пределами своей папки.
